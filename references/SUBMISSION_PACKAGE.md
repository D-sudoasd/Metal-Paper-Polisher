# 投稿配套材料（v5）

本文件覆盖论文正文之外、决定编辑第一印象的投稿材料：Highlights、Cover Letter、图形摘要文案、一句话总结和意义陈述。所有材料与正文共享同一主张集合和同一证据等级；配套材料不得比正文写得更强。

## 1. 共同约束

1. 配套材料中的每一个主张必须能在正文定位，且不超过正文的 L0–L7 证据等级。
2. 配套材料是最常发生"静默升级"的位置：正文写 `is associated with`，Highlights 写成 `governs`，属于必须修正的漂移。
3. 数值必须与正文完全一致（含单位、有效数字和测试条件）。
4. 不使用 novel、first、unprecedented 等优先权词，除非正文提供了明确的检索范围和比较口径。

## 2. Highlights（Elsevier 系）

### 2.1 格式事实

- 3–5 条（Cell Press 系 3–4 条）；每条 ≤85 字符（含空格），逐字符核对；
- 独立文件提交；面向搜索引擎与快速浏览，避免行话、缩写和首字母词；
- 覆盖核心结果与新方法，不求覆盖全部结论。

### 2.2 写作规则

1. 每条一个主张，主张按重要性降序排列；
2. 首条通常为最重要的定量结果或核心机制认识；
3. 优先使用完整可检索的关键词（合金体系、机制名、性能指标）；
4. 动词强度受正文证据等级约束；85 字符不构成升级为强因果的理由；
5. 逐条报告字符数，超限的先压缩修饰语，再压缩条件，最后拆分主张。

### 2.3 结构模板

```text
条 1：核心定量结果（指标 + 数值方向 + 体系）
条 2：实现该结果的设计/工艺/条件
条 3：机制认识（与正文同强度）
条 4（可选）：方法或表征进展
条 5（可选）：适用边界或设计含义
```

### 2.4 常见失败

| 失败 | 表现 | 修正 |
|---|---|---|
| 强度升级 | 正文 suggest，Highlight 写 demonstrate | 与正文同级 |
| 无信息量 | "Microstructure was characterized by TEM" | 换成结果本身 |
| 超字符 | 挤入两个主张 | 一条一主张 |
| 缩写堆叠 | "HEA w/ B2+FCC via LPBF" | 展开为可检索词 |

## 3. Cover Letter

### 3.1 功能与长度

- 通常 250–450 词；对象是处理编辑，不是审稿人；
- 回答三个问题：这篇论文建立了什么、为什么适合本刊、有哪些必要声明。

### 3.2 段落结构

```text
段 1：投稿声明 + 题目 + 文章类型。
段 2：核心科学主张（2–4 句）：问题 → 本文动作 → 最重要结果 → 认识增量。
       与摘要不同：面向编辑说明"相对已有认识前进了哪一步"，而非复述摘要。
段 3：期刊契合度：明确说明为什么属于该刊范围（如 Acta 系说明 PSPP 链条完整性；
       Nature 系说明跨领域意义；快报说明进展的时效性与单一性）。
段 4：声明：原创性、无一稿多投、利益冲突、数据可用性；如为被拒转投或重投，
       说明修改概况。
段 5：可选：建议/回避审稿人及理由；通讯作者信息。
```

### 3.3 规则

1. 段 2 的主张强度与摘要一致；cover letter 不是升级结论的场合；
2. 不复制摘要原文；用"认识增量"视角改写：before（已有认识）→ now（本文建立）；
3. 契合度论证引用期刊定位的事实（范围、体裁），不写恭维语；
4. 篇幅、图数、补充材料构成如与期刊要求相关（如 Acta 的 11,000 词软上限），在信中主动说明。

## 4. 图形摘要（Graphical Abstract）

技能不生成图像，但可产出**图形摘要设计稿**：

### 4.1 设计稿内容

```text
版式：单幅横版（Elsevier 要求约 531×1328 px，5×13 cm 可读）。
叙事：从左到右或从上到下，对应论文主线的 2–4 个环节。
面板规划：
  面板 1：[起点：设计/工艺/初始组织]
  面板 2：[关键过程或证据：原位曲线示意/组织演化]
  面板 3：[落点：定量性能对比或机制示意]
标注文字：每面板 ≤6 词的标签；避免完整句子。
禁止：正文没有的机制示意；未测量的中间态画成已观测；
      性能图中混入不可比文献数据。
```

### 4.2 规则

1. 图形摘要讲述与摘要相同的主线，不引入新证据或新机制箭头；
2. 机制示意图（原子、位错、界面卡通）必须对应正文已建立的机制等级：正文为 L3 关联时，示意图不画成单向因果箭头链；
3. 面板中的数据缩略图必须来自论文实际图表。

## 5. 一句话总结（Science 系）与编辑短评素材

- ≤125 字符（含空格），独立于摘要；
- 形态：`[体系/材料] + [核心发现动词] + [最重要落点]`；
- 动词强度与正文一致；逐字符核对并报告；
- 同样的产物可用作会议报告标题、成果快讯与机构新闻素材的种子句。

## 6. 意义陈述（Significance / Impact Statement）

部分期刊（PNAS 型、部分学会刊）要求 100–120 词的意义陈述：

```text
句 1–2：该问题为什么对领域外读者也重要。
句 3–4：本文建立了什么（与摘要同强度）。
句 5：这个认识使哪类研究或设计成为可能（有正文依据时）。
```

规则：意义陈述面向非专业读者，允许减少技术细节，但不允许把 L3–L4 结论升级为 L6 宣言，也不允许添加正文未建立的应用前景。

## 7. 投稿包整体核查

输出投稿包（正文之外任一材料）时确认：

- [ ] 每个主张可在正文定位且等级不升；
- [ ] 数值、单位、条件与正文一致；
- [ ] Highlights 每条 ≤85 字符且已报告字符数；
- [ ] 一句话总结 ≤125 字符且已报告字符数；
- [ ] Cover letter 无摘要复制，契合度论证具体；
- [ ] 图形摘要设计稿不含正文未建立的机制箭头;
- [ ] 优先权词（first、novel、record）均有正文比较口径支持，否则删除；
- [ ] 所有材料使用同一套术语、符号和材料命名。
